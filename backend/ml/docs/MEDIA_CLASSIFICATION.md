# Media types and private search descriptors

Media classification is separate from link detection. RSS and `Article` markup describe delivery/structure, so neither proves an item is a blog. The saved media type uses bounded title, description, URL-path and entry-pattern evidence. Chapter sequences combined with manga/manhwa/comic descriptions take precedence over generic feed evidence. No domain-specific manga rule was added.

Users can choose a type during **Review & save**, or in **Settings → Item settings → Media type**. Automatic uses the detected type. Overrides survive lightweight/full refreshes, imports, restarts and model updates, and never change the scraping adapter. Existing libraries migrate using saved titles and up to 32 saved entries, without fetching sources. Richer descriptors arrive on the next normal refresh.

Each item stores up to 48 private descriptors from its title, source description, a bounded entry sample and available language labels. Description metadata and up to 48 existing paragraphs are considered; navigation, link-heavy lists, oversized paragraphs and SEO keyword metadata are excluded. Sidebar descriptions must share at least two meaningful title words with the current page. Source text is capped at 2,400 characters. Common words and duplicates are pruned. Controlled aliases map concepts such as scuba/diving and college/university to shared search terms. These are retrieval hints, not verified facts or generated plot summaries.

The library builds sparse TF-IDF vectors once per metadata change and computes cosine similarity locally while typing. All query words must match, exact title/URL/filename matches rank higher, and favorite/muted ordering remains in force. Suggestions reuse the same hidden descriptors in their existing TF-IDF profile. No extra scraping, external embedding API, vector database, or new runtime ML dependency is needed. Account libraries remain isolated; corrections are not collected as global training data. Hidden descriptors are included in the existing account export/deletion lifecycle.

## Dedicated model experiment

`uv run --group ml python ml/evaluate_media.py` reproduces the comparison using the committed public metadata corpus. Optional `--capture` rebuilds it from existing local public captures and labeled link fixtures; it performs no network requests. The 47 listings cover 46 domains and 10 classes. Five-fold domain grouping keeps sources on the same domain together. Each listing is one observation, irrespective of its number of links.

The comparison includes the previous type heuristic, the new evidence classifier, balanced logistic regression, and a 24-unit neural classifier. All candidates use the same 45 bounded evidence features. [Recorded results](../reports/media-classification.json) include per-source errors, timing and class counts. This is an exploratory development-corpus comparison, not a blind production accuracy estimate. Several classes have only one or two sources; music and jobs have none. Neither learned candidate is promoted automatically.

The production evidence classifier is currently more accurate on this corpus. A dedicated learned classifier remains promising: gather independently labeled collection profiles from at least 5–10 distinct domains per class, add hard negatives such as manga-news blogs and podcast-news articles, and reserve an untouched domain holdout. Compare text word/character features plus structural features, linear models and a small neural network. Evaluate per-class precision/recall, abstention on ambiguous sources, descriptor retrieval quality, latency and memory. Promote only after improving the held-out result without regressions on existing media types. Manual corrections remain available regardless of model confidence.

Useful references: [scikit-learn's sparse text classifier comparison](https://scikit-learn.org/stable/auto_examples/text/plot_document_classification_20newsgroups.html) and [fastText's supervised text classification tutorial](https://fasttext.cc/docs/en/supervised-tutorial.html).
